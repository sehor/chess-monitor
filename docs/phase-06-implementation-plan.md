# 阶段 6 实施计划

## 范围

在不改变阶段 0–5 已有公开 IPC/棋局语义的前提下，加固单客户端可靠性。所有不确定状态都必须拒绝提交、暂停或进入 `DESYNC`，禁止静默推进棋谱。

## 任务 1：稳定帧与故障回放

- FrameAnalyzer 对全局变化/短时遮挡冻结参考基线，遮挡消失后仍以遮挡前基线判断真实落子。
- BoardTracker 丢弃重复/乱序观测；运动期间出现过长帧间隔时进入 `DESYNC`。
- 扩展确定性回放故障注入，覆盖丢帧、重复帧、乱序、动画、高亮、短时遮挡和 Profile 失效。
- 验证：相关 Vitest 先失败后通过；1,000 步基准静默失步保持 0。

## 任务 2：Worker/引擎恢复边界

- Recognition Worker 增加有上限的连续失败熔断与冷却，防止崩溃循环。
- 保持 generation/version 隔离，恢复后只允许当前扫描结果生效。
- 验证：模拟连续 Worker 崩溃、超时、冷却恢复；现有 Pikafish 重启测试继续通过。

## 任务 3：SQLite 恢复与一致性

- 设置 `busy_timeout`，所有关键写入保持事务性。
- 增加完整性检查与在线备份入口，迁移继续使用显式事务回滚。
- 验证：busy/写失败不产生幽灵着法；备份可重新打开并恢复已有棋局。

## 任务 4：结构化诊断与长稳观测

- 统一可靠性事件字段：session/game、positionVersion、frame/analysis 标识、错误码、时间戳。
- 诊断导出包含 tracker、引擎/Worker 状态、Profile/版本和近期可靠性事件；设置有界内存保留。
- 增加可重复执行的长稳/故障注入脚本与报告模板，不在自动化测试中硬等待 8 小时。
- 验证：单测、类型检查、构建和全量 smoke 通过。

## 完成门槛

- 静默错误计数为 0。
- 不确定观察不会自动确认着法。
- 旧 generation / 旧 positionVersion 的异步结果不会回写当前状态。
- 数据库写失败时 UI/内存状态不越过持久化状态。
- 8 小时长稳验收由可执行脚本产出最终报告；本阶段代码提交前至少完成缩短版自动化验证。
