# 阶段 8 实施状态

## 2026-08-19 审查修复

- 整盘复盘在启动时固化节点快照；实时棋局新增节点不会改变当前任务总量或触发无限调度。
- v3 数据库每次打开都会补齐缺失的研究根节点，并兼容早期 v3 的复盘节点快照列，迁移中断后可自动修复。
- 跨棋局交互分析会记住并恢复被抢占的原复盘；外部停止研究引擎会把任务置为失败，不再保留虚假的运行状态。
- 评估曲线只连接当前选中节点的祖先分支，不再跨兄弟变化画线。
- 强制将杀判定补充“走前己方有将杀、走后丢失将杀”的漏着语义。
- 新增上述边界及阶段 07 安全修复的自动化回归；当前完整 smoke 为 26 个测试文件、334 个测试。


## 已实现

- SQLite schema v3：在现有自动保存棋局之上增加不可变 `position_nodes`、父子关系、来源标签、分析缓存、节点分析关联、疑问手/漏着标记和可恢复复盘任务。
- 实时主线、重同步、撤销、用户分支、导入棋谱和独立 FEN 研究局面使用同一节点模型；历史节点不会反写 Board Tracker 当前局面。
- 实时分析与研究分析拆分为两个独立 `EngineManager` 实例。选择同一 Pikafish 后分别维护进程和 analysisId，历史/复盘任务不会停止或覆盖实时分析。
- 研究分析缓存键包含 Pikafish SHA-256、FEN、MultiPV 和深度；相同局面和参数可跨节点复用，分析记录保留 FEN、引擎指纹、设置、PV、分值和生成时间。
- Vue 高级分析工作区：已保存棋局选择、变化树、历史/实时状态提示、前进后退、回到实时、分支落子、棋盘翻转、单步重分析和最佳着箭头。
- FEN 草稿编辑：合法 FEN 可保存为独立研究节点；非法 FEN 保留在输入框并拒绝提交，不调用实时重同步。
- 棋谱导入/导出：支持标准 FEN 与离线文本格式 `CHESS-MONITOR-ICCS 1`；内部着法统一为 ICCS。未知格式、未知字段、非法 ICCS 或非法走子均给出明确错误。
- 历史评估曲线：只绘制最多 200 个采样 cp 点；mate 结果使用独立标记，不把 mate 数值混入 cp 曲线。曲线点可追溯到节点 FEN、引擎 SHA-256、深度/MultiPV 和分析结果。
- 整盘复盘：单并发顺序调度，支持暂停、继续和 SQLite 断点恢复；交互式历史分析可以抢占研究引擎，完成或失败后再继续运行中的复盘，且抢占不会错误推进复盘游标。
- 疑问手/漏着：默认实战着偏离最佳着且损失 ≥ 80 cp 标记疑问手，≥ 180 cp 标记漏着；新进入对行棋方不利的强制将杀直接标记为漏着。标记说明保留实际着、最佳着、损失或 mate 语义。

## 自动化验收证据

- 变化树：创建 100 个分支节点后关闭并重开 SQLite，101 个含根节点的 ID、FEN、父子关系保持完全一致。
- 棋谱往返：50 盘合法 ICCS 测试棋谱执行导入 → 保存 → 导出，根 FEN 和主线着法语义保持一致。
- 快速版本切换：既有 Engine Manager 与 Realtime Coordinator 测试覆盖 100 次连续 positionVersion 切换，过期分析不会进入最新局面。
- 复盘恢复：数据库测试连续执行 20 次暂停/继续后重开，`nextIndex`、`completedNodes` 和任务参数保持一致。
- 分析隔离：Study Coordinator 测试验证交互历史分析抢占复盘时不推进复盘游标，完成后复盘从原断点继续。
- 缓存：同 FEN、同引擎 SHA-256、同 MultiPV/深度的不同节点只运行一次引擎分析，并分别关联到两个节点。
- 非法输入：非法 FEN、非法 ICCS、非法走子、损坏或不支持的棋谱格式均在持久化前被拒绝。

## 仍需目标设备人工复核

自动化能够证明数据模型、隔离、缓存、恢复和输入边界，但不能替代真实桌面交互证据。进入阶段 9 前仍应在目标 Windows 10/11 设备上完成以下复核：

- 真实 Pikafish 二进制同时运行实时分析与研究/复盘时，确认两个进程的 CPU/内存开销可接受，实时 Board Tracker 更新不被研究任务拖慢。
- 在真实长棋局上反复切换历史/实时视图、分支和曲线点，确认键盘操作、布局和棋盘箭头符合预期。
- 使用真实用户棋谱补充格式兼容性样本；当前明确支持范围只有标准 FEN 与 `CHESS-MONITOR-ICCS 1`，未声称兼容 PGN/XQF 等格式。
- 验证大量棋局和长期分析缓存下的 SQLite 文件增长、查询延迟和备份/升级体验。
