# 阶段 8：高级分析功能

## 目标

在可靠监控链路之上增加面向研究和复盘的能力：变化树、分支分析、局面/FEN 编辑、历史评估曲线、棋谱自动保存、前进后退、单步重分析、整盘复盘以及疑问手/漏着标记。

这些功能不得改变 Board Tracker 的实时事实来源，也不得让历史分支结果覆盖当前对局的实时分析。

## 工具选择

- Vue 3：变化树、编辑器、曲线、复盘控制和筛选界面。
- xiangqiground：历史局面、编辑模式和分支箭头。
- `@west-shell/xiangqi.js` 适配层：分支合法性、FEN/棋谱导入导出和局面推演。
- Pikafish Engine Manager：带优先级的实时与后台分析任务。
- SQLite：游戏、节点、父子关系、着法、FEN、分析快照和标记。
- 图表库：优先选择项目中已使用且支持离线打包的轻量方案；只绘制采样后的评估数据。

## 技术路线

1. 将棋局建模为不可变 Position 节点和有向父子关系。实时主线、用户分支和导入棋谱使用同一结构，但有明确来源标签。
2. 实时节点优先级最高；进入历史节点时不停止后台监控，UI 必须显著显示“查看历史”并提供一键返回当前局面。
3. Engine Manager 增加任务优先级和缓存键：引擎版本、选项、FEN、深度/时限。历史分析不得覆盖当前 `positionVersion`。
4. 局面编辑器逐步落子并即时校验；非法局面可以暂存草稿，但不能提交给实时跟踪或标记为可信局面。
5. 实现 FEN 和选定棋谱格式的导入导出，内部仍以 ICCS 坐标着法和标准 Position 为准。对规则库不足的格式做显式能力边界。
6. 保存每步统一深度或时限下的评估快照，生成历史曲线；mate 分值用单独语义显示，不直接当普通分数绘制。
7. 整盘复盘顺序调度分析，支持取消、继续和断点恢复，限制并发和数据库写入频率。
8. 疑问手/漏着采用可解释规则：实战前后评估变化、最佳线差异和阈值；保留引擎版本和参数。

## 交付物

- 变化树和分支分析界面。
- 局面/FEN 编辑器与导入导出。
- 历史评估曲线、前进后退和回到实时局面。
- 自动保存棋谱和整盘复盘队列。
- 疑问手/漏着标记及其参数说明。

## 验收标准

- 创建至少 100 个分支节点后，保存、重开、导航和父子关系全部一致。
- 对不少于 50 盘测试棋谱做导入 → 保存 → 导出往返，局面主线和着法语义保持一致；不支持的格式或字段给出明确告警。
- 浏览历史、编辑分支和整盘复盘期间，实时 Board Tracker 继续接收局面；返回实时视图后无漏步且版本一致。
- 快速切换历史与实时节点 100 次，分析结果跨节点污染次数 = 0。
- 中止并恢复整盘复盘 20 次，不重复生成冲突节点，不丢失已完成分析。
- 非法 FEN、非法走子和损坏棋谱均被拒绝或进入草稿，不影响当前实时棋局。
- 历史曲线的每个点能追溯到 FEN、引擎版本、选项和分析限制。
