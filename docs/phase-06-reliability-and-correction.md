# 阶段 6：稳定性与纠错

## 目标

把单客户端 MVP 提升为可长时间运行、可复现故障、可自动恢复的可靠版本。系统需要正确处理动画、高亮、漏帧、窗口移动、短时遮挡、悔棋、局面跳转、Worker/引擎崩溃和数据库异常。

核心质量目标不变：无法确定时进入候选、暂停或 `DESYNC`，静默错误必须为 0。

## 工具选择

- 离线回放框架：帧、时间戳、Profile、正确棋谱和故障事件的确定性重放。
- Vitest：状态机、评分、迁移和恢复策略的单元/集成测试。
- 结构化日志：统一 sessionId、gameId、positionVersion、frameId、analysisId 和错误码。
- SQLite：诊断会话索引、棋局、失败事件和资源版本；大图像按保留策略存文件，数据库只存元数据。
- Windows 性能计数或 Node 进程指标：CPU、内存、句柄、事件循环延迟和子进程存活。
- 可控故障注入：丢帧、重复帧、乱序、Worker 退出、引擎退出、数据库忙和 Profile 失效。

## 技术路线

1. 把阶段 0–5 的失败帧整理为版本化回放集，建立真实样本、合成边界样本和故障注入样本三类套件。
2. 增强稳定帧逻辑：多帧确认、动画结束、鼠标高亮与选中效果过滤、短时遮挡冻结、捕获源无效检测。
3. 增强候选评分和恢复：候选差距门槛、连续漏帧、多步间隔检测、悔棋/局面跳转识别以及自动重扫。
4. 窗口移动或尺寸变化时暂停提交，通过 Profile 重定位；只有 90 点重新验证后才恢复。
5. 对每次拒绝、DESYNC 和重同步保存最小诊断包：前后关键帧、Profile、变化热力、候选着法、Position 哈希、日志和软件/模型版本。
6. 对 Pikafish 和 Recognition Worker 建立有上限的自动重启、退避和熔断策略，防止崩溃循环无限占用资源。
7. 建立数据库备份、事务、忙超时和迁移失败回滚；诊断数据设置容量与保留上限。
8. 进行 8 小时以上长稳运行，观察内存、句柄、临时文件、日志和进程数量是否持续增长。
9. 每个已修复故障必须先加入离线回放或自动化测试，再关闭问题。

## 交付物

- 版本化离线回放框架和不少于 1,000 步的基准集。
- 稳定帧、纠错、重定位和自动重扫增强。
- 结构化日志、诊断包和一键导出。
- 故障注入套件与长稳测试报告。
- 数据保留、崩溃重启和数据库恢复策略。

## 验收标准

- 基准回放集不少于 1,000 个标注着法，静默失步数 = 0，确认着法准确率 ≥ 99.9%。
- 对丢帧、重复帧、动画中间帧、高亮、短时遮挡和窗口移动各至少 50 个样本，错误确认数 = 0。
- 强制制造 100 次可恢复 DESYNC，自动或人工辅助恢复成功率 ≥ 99%。
- 50 次 Pikafish 崩溃和 50 次 Recognition Worker 崩溃均不会使主应用退出；恢复后只处理当前版本任务。
- 连续运行 8 小时，内存和句柄在预热后无持续线性增长；子进程数量回到设计上限，诊断数据不超过配置容量。
- 数据库忙、写入失败或迁移失败时，不产生已显示但未持久化的幽灵着法；已有棋局可恢复。
- 每个失败案例都能在 1 分钟内导出包含版本、关键帧、Profile、候选和日志的诊断包。
