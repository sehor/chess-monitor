# 阶段 2：Profile 与棋盘监控

## 目标

把阶段 0 的临时校准变成可持久化、可恢复、可诊断的 Profile 系统。用户选择目标窗口并点击两个基准交叉点后，软件生成 90 个交叉点；关闭并重新打开软件后，能重新匹配窗口并恢复正确棋盘区域。

本阶段只支持一个目标客户端和一个已验证主题，但数据结构从一开始允许版本化和后续扩展。

## 工具选择

- Electron 主进程：窗口发现、捕获会话和生命周期管理。
- Vue 3：窗口选择、两点校准、方向选择和测试预览界面。
- `sharp`：ROI 预览和校准截图生成。
- SQLite：Profile、应用设置和 schema 版本持久化。
- TypeScript schema validator（优先项目已选的轻量库）：读取外部或旧版本 Profile 时做运行时校验。
- Vitest：Profile 迁移、坐标恢复和窗口匹配策略测试。

## 技术路线

1. 定义版本化 Profile：客户端标识、窗口匹配规则、棋盘矩形、两个基准点、90 点网格、方向、DPI/缩放、主题、ROI 比例、变化阈值、稳定帧和动画等待参数。
2. 区分可重算数据和用户输入：90 点坐标由棋盘矩形与方向重算，不把 90 个像素点作为唯一事实来源。
3. 建立选择窗口 → 捕获预览 → 点击两个基准点 → 预览 90 点覆盖层 → 选择红黑方向 → 保存 Profile 的向导。
4. 保存窗口的稳定特征组合，而不是只保存瞬时窗口句柄。匹配结果为 0 或多个时必须要求用户选择，不能悄悄连接错误窗口。
5. 每次捕获校验窗口尺寸、DPI 和棋盘边界；尺寸变化时根据相对坐标重算，超出安全误差则转入 `CALIBRATING`。
6. 建立 Profile schema 版本和迁移机制。迁移失败保留旧记录、显示可恢复错误，并允许导出诊断信息。
7. 提供“测试 Profile”：在当前帧叠加 90 点和 ROI，显示每点裁剪预览、方向及边界告警。
8. 主进程向 Renderer 只发送必要的缩略预览或状态，不持续传输无界原始帧。

## 交付物

- Profile 数据模型、SQLite 表和首个迁移版本。
- 窗口选择与棋盘校准向导。
- 90 点/ROI 可视化测试界面。
- 启动时窗口重匹配与失败处理。
- Profile 诊断导出样例。

## 验收标准

在目标客户端、三个 DPI 档位和至少三种窗口位置/尺寸组合下完成 30 轮“创建 → 关闭软件 → 移动目标窗口 → 重开 → 恢复”测试：

- 唯一目标窗口存在时，正确窗口匹配成功率 ≥ 99%。
- 恢复后的交叉点最大误差不超过相邻线距的 10%。
- 找不到窗口或匹配到多个窗口时，错误连接次数为 0，并给出可操作提示。
- 窗口尺寸或 DPI 超过已验证范围时，系统进入重新校准，不继续使用失效坐标。
- Profile 数据库升级测试全部通过；故意注入损坏记录时不会导致应用无法启动。
- 删除或重建 Profile 不影响已保存棋局和引擎设置。
